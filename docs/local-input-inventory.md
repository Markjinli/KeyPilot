# 本机输入设备只读快照

采集时间：2026-08-01。该快照只用于决定开发期默认监听范围，不把任何设备直接认定为掌机特殊键。

## 结果摘要

- Raw Input 共枚举到 26 个设备/顶层集合。
- XInput 1.4 可正常调用，但 750ms 探测期间没有已连接用户槽。
- 存在多个 Consumer Control 顶层集合：`Usage Page 000C / Usage 0001`。
- 存在以下厂商自定义候选；必须在实际按键测试后才能命名：

| VID:PID | Usage Page / Usage |
|---|---|
| `0C45:8006` | `FF13/0001`、`FFFF/0001` |
| `372E:103D` | `FF06/0001` |
| `0C45:FEFE` | `FF59/0061`、`FF60/0061`、`FFFF/0001` |
| `00FF:BACC` | `FFAA/00BB`、`FFEE/00CC`（路径标识为 GVInput，可能是虚拟设备） |

另有 `0C45:FEFE` 的 `0001/000E` Generic Desktop 集合。为了避免与既有键盘、鼠标或未来 XInput 事件重复，第一轮 HID 注册不对整个 `Usage Page 0001` 使用通配符。

## 约束

- 配置匹配保存完整设备路径；VID/PID/Usage 只用于显示或用户明确选择的“同型号任意设备”。
- 厂商报告先作为不透明字节差分显示，不根据 VID/PID 猜按键名称。
- 只有观察到稳定的“离开基线—回到基线”或 HidP 明确按钮数据后，才允许绑定为特殊键。
- 此流程仍是只读采集，不能屏蔽 Windows 原输入。
